# wss_data_test

Recodes and analyzes a large set of Western States Survey (WSS) data, organized
for reproducibility, replication, and open science.

## Repository structure

```
.
├── data/
│   ├── raw/          # Original, immutable data as received (read-only; never edited)
│   ├── external/     # Third-party data (e.g., Census, shapefiles) with provenance noted
│   ├── processed/    # Analysis-ready data generated ONLY by code/ scripts
│   └── README.md     # Data provenance, access, licensing, sensitivity notes
├── code/
│   ├── 01_cleaning/  # Raw -> cleaned data (no substantive recodes)
│   ├── 02_recoding/  # Cleaned -> analysis-ready variables, documented in codebooks/
│   ├── utils/        # Shared helper functions
│   └── run_all.sh    # Executes the full pipeline in order
├── analysis/
│   ├── scripts/      # Analysis scripts (models, descriptives) reading data/processed
│   └── output/
│       ├── figures/  # Generated figures
│       └── tables/   # Generated tables
├── codebooks/        # Variable-level documentation (raw and recoded variables)
├── docs/             # Preregistration, protocols, supplementary materials
├── CITATION.cff      # How to cite this repository
├── LICENSE-NOTE.md   # Licensing guidance (code vs. data)
└── .gitignore
```

## Workflow

1. Place original data in `data/raw/` (never modify it). See `data/README.md`.
2. Run cleaning scripts in `code/01_cleaning/`, then recoding in `code/02_recoding/`.
   Outputs go to `data/processed/`.
3. Run analyses in `analysis/scripts/`; outputs go to `analysis/output/`.
4. Document every created/recoded variable in `codebooks/`.

Run everything with `bash code/run_all.sh`. Scripts are numbered to indicate
execution order, use relative paths from the repository root, and set random
seeds explicitly.

## Reproducibility standards

- **Raw data are immutable**; every derived file is regenerated by code.
- **Scripts run top to bottom** with no manual steps.
- **Record the computing environment** (e.g., `renv.lock` for R, `requirements.txt`
  for Python) and software versions in `docs/`.
- **Set and document seeds** for any stochastic procedure.
- **Version control** all code, codebooks, and documentation.
- **Preregistration/protocols** go in `docs/`.
- Large or restricted data are not tracked in git; deposit them in a repository
  (e.g., OSF, Dataverse) and link the DOI in `data/README.md`.

## Open science

Code, codebooks, and (where permissible) data should be archived on OSF or a
similar repository with a DOI. Update `CITATION.cff` upon release.

## Contributing / replication

To replicate: clone, obtain data per `data/README.md`, install the environment,
run `bash code/run_all.sh`.
